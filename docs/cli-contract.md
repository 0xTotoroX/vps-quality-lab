# CLI contract · v1

The process entry point is `vps-lab`. Options use long GNU-style names. `--help` and `--version` work without network. No command prompts for missing input. `--json` may appear before or after the command; stdout is exactly one JSON document, including help and errors. Progress goes to stderr. Configuration/result schemas are generated by `schema --kind config|result` and embedded in a versioned envelope.

| Command | Input and observable output | Side effects |
| --- | --- | --- |
| `init` | Required host, expected-exit, interface, known-hosts, output; creates validated config | New private local config; refuses overwrite |
| `schema`, `plan` | Schemas; selected stages, route/plan/endpoints, limits, local references and declared effects | No server connection; missing local references make plan partial |
| `trust-host` | Host/port + trusted SHA256 fingerprint → known_hosts | Adds verified key only; no silent trust-on-first-use |
| `doctor` | Config → local tools, Debian/Ubuntu inventory | Read-only SSH and local checks |
| `ssh-bootstrap` | Config → configured/verified, alias and config path | Reuses existing public-key login or adds one dedicated key, local backup, fresh BatchMode check |
| `ssh-status` | Config → fresh public-key readiness | Separate read-only SSH connection |
| `run` | Config, optional stages/label → run directory and result | Selected pipeline steps and private evidence |
| `resume` | Run directory → new attempt; `--rerun` repeats completed measurements | Rechecks live prerequisites; preserves previous attempts |
| `status` | Run directory → saved result | Read-only, historical status |
| `node-export` | Run directory + new output directory | Private URI, JSON and QR copies; stdout contains only paths |
| `client-import` | Run directory → imported or import_requested | Native macOS add-only import request; no selection change |
| `client-check` | Optional archive and local proxy → imported/verified | Read-only archive; optional two-source exit requests; saves evidence |
| `capture` | Raw ANSI + PNG destination → capture provenance | Offline xterm replay and browser screenshot |
| `report` | Run directory; output or Obsidian; optional share | Markdown + original PNG copies; never exports node/SSH credentials |
| `compare` | At least two run directories → eligible ranking and exclusions | Read-only; rejects unequal profiles, endpoint lists or measurement shapes |

Exit codes: `0` completed command; `1` failed execution or essential stage; `2` invalid/missing input; `3` partial/skipped or incomplete client delivery; `4` failed precondition, ownership/identity/safety check; `5` run already active; `130` interrupted. A pipeline stores its stage-specific `error_code` and exits `1` for an essential failure. `status` exits `0` when a saved record was successfully read; inspect its `status` for historical outcome.

Every measurement uses `success`, `partial`, `failed` or `skipped`. A skip never becomes zero or success. Lifecycle is separately `running`, `complete` or `interrupted`. Node delivery is separately `not_generated`, `generated`, `import_requested`, `imported`, `verified`; SSH delivery is `not_configured`, `configured`, `verified`. Independent sing-box verification does not upgrade the Shadowrocket delivery state.

## Pipeline and persistence

Order: `ssh,check,node,verify,hardware,ip,network,routes,net,hardware-full,screenshots,report`. Explicit stages automatically include prerequisites. `all` includes only the upstream tools named in `external_tools`. `hardware` collects inventory and, only when authorized, a bounded one-thread SHA256 sample. HardwareQuality uses `hardware-full` and requires `allow_stress`. UDP and application/account tests are explicitly outside these TCP HTTP samples.

Default storage: `~/.local/share/vps-quality-lab` (override with `VPS_LAB_HOME`). Each run has immutable `private/config.json`, `private/node.{json,txt,png}`, `state.json`, `evidence/attempt-NNN/`, `report.md` and `report-share.md`. Private directories are mode 700; files 600. Identity files and managed SSH aliases persist under `identities/<host digest>/`. The tool does not rewrite `~/.ssh/config`.

Resume validates the config digest and obtains locks. SSH, system checks, node ownership and exit are checked again. Completed measurement data retain their original timestamps; use `--rerun` or a new labeled run for a fresh sample. A changed node invalidates its dependent measurements. Interrupted stages stay partial; no fabricated metrics replace missing evidence. A failed exit check removes ranking eligibility, including for saved measurements.

New Xray deployment requires `mode=deploy` and `allow_deploy=true`, root, an available port and an unowned fresh installation target. The pinned official installer checks release SHA256. Existing services require `mode=adopt`. Managed pending keys are stored before activation and reused after interruption. The tool never installs WARP, opens firewalls or changes the system proxy. SSH public-key enablement is separately gated by `ssh.enable_public_key`; it is a user-scoped, syntax-checked policy change with backup, protected-setting comparison and rollback after a failed fresh-key test. Password/root/port settings are not changed.

## Bounds and evidence

SSH connect timeout 2–60 s; per-request timeout 3–120 s; 1–10 samples; 100 KB–50 MB downloads; 100 KB–10 MB uploads; 1–4 parallel connections. External diagnostics have a 30–900 s wall limit, systemd CPUQuota=100%, MemoryMax=512M, TasksMax=256 and RuntimeMaxSec. Missing systemd resource support produces failure, not an unbounded fallback. Interrupted scoped tools are stopped; transport failures still leave a finite remote timeout. Upstream dynamic helper downloads may still fail despite a pinned entry script.

Two independent HTTPS exit checks gate measurement and are repeated afterwards. A wrong/missing exit cannot enter ranking. Failed HTTP or incomplete byte transfers are invalid samples. Parallel throughput uses completed bytes divided by wall time. TTFB cold/warm pairs retain curl `num_connects`. TCP, source-bound ICMP, return TCP/ICMP, server-to-endpoint cross-checks and UDP are separate fields.

Original ANSI and upstream JSON are retained together. Screenshots are literal xterm.js browser pixels from the raw ANSI, with source SHA256 and renderer provenance, not OCR or recreated report text. Known IPQS conflicts are explicit; unknown upstream fields remain available for review. An upstream process exiting 0 without meaningful JSON is not success.

NetQuality runs in low-data mode: Speedtest and iperf throughput are explicitly skipped; independent HTTP measurements provide throughput. Required latency fields need numeric observations, not location labels. Process creation failures inside the resource scope are incomplete diagnostics and cannot establish poor VPS/network quality. Screenshots select the latest attempt's final report (up to 300 lines) or last 120 terminal lines; the complete raw ANSI remains on disk.

Share export removes original evidence and common identifiers. Treat all full runs/exports as private: they may contain public IPs, package details and local paths. Passwords are accepted only through a named environment variable; SSH keys and node credentials never appear in normal stdout, logs, Git or release packages.
